# 非 RUL 目标训练重建执行台账

**状态：** 检查点 0——开发实施顺序与来源映射待审；尚未进入目标级 TDD。  
**范围：** SOC、SOE、SOH、SOT；RUL/v11、RUL 数据、标签、配置、审计和历史产物全部冻结、只读。  
**唯一更新规则：** 测试工程师对每一目标在每一检查点给出明确 PASS/FAIL 后，才可更新该目标的下一状态；任何 PASS 不外溢至其他目标。

## 固定执行顺序

1. 开发提交四目标的简洁实施顺序、现有来源映射、标签合同、角色映射、严格留出与验收命令；此阶段只读，不改代码。
2. 测试工程师独立审阅该计划。仅计划审阅 PASS 的目标才可进入目标级 TDD。
3. 检查点 1：逐目标数据/manifest/admission 预检，确认零 RUL 字段、样本与授权依赖，拒绝 `INVALIDATED` 数据并审计泄漏。
4. 检查点 2：仅检查点 1 PASS 的单目标最小烟雾，由测试工程师按既有正式合同验收。
5. 检查点 3：仅烟雾 PASS 的目标串行正式训练；每目标保存独立配置、日志和结果。

## 全目标硬门

- 不下载新数据；现有来源不足、许可证不明确或 manifest 不可复核时，目标停在来源缺口并上报。
- 每个目标独立 manifest、标签合同、角色映射、严格电芯/工况留出、泄漏审计和结果目录。
- SOC 与 SOE 可共享因果原始时序读取层；标签、准入、训练、配置和结果不得共享。
- `v9`/`v10` 的 `INVALIDATED` 数据全部拒绝；RUL/v11 与所有 RUL 资产不得读写或混入新运行。
- XGBoost 仅在无 Torch 的隔离 worker 中拟合；Torch 与 XGBoost 不得在同一解释器拟合。
- Python 崩溃、SIGSEGV、OpenMP/libomp/XGBoost 冲突、非零退出、测试失败或数据门禁失败，立即停止**该目标**并上报；其他目标按自身状态继续。

## 当前禁止项

在开发计划获得测试工程师明确 PASS 前，禁止目标级 TDD、数据读取、manifest 写入、实现、最小烟雾、正式训练及结果目录创建。

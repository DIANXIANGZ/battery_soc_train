# 跨数据集 SOC 科研模型总体设计

日期：2026-07-21  
状态：设计已由用户确认，等待书面复核  
适用项目：`battery_soc_project`

## 1. 目标与范围

第一版目标是建立同一电池化学体系内，能够跨数据集、跨电芯、跨温度、跨工况和跨老化状态进行 SOC 估计的科研级训练与评估系统。第一版不将不同化学体系直接混合训练；跨 LFP、NMC 等化学体系的联合建模属于第二版独立研究。

最终产物不是单个最低 MAE 模型，而是由数据治理、标签生成、泄漏防护、基线比较、跨域验证、不确定性评估和可复现交付组成的完整科研证据链。

当前 A123#3 与 A123#5 结果作为历史基线保留。所有新增数据、模型和实验必须写入独立版本目录，不得覆盖现有产物。

## 2. 科研结论边界

第一版可以回答：模型在已声明的同化学体系、数据来源、温度、工况和老化范围内，能否对未见数据集或未见电芯稳定预测参考 SOC。

第一版不能直接声称：

- 模型适用于任意电池化学体系；
- 模型达到真实车辆 BMS 的部署标准；
- 库仑计量标签等同于物理真实 SOC；
- 单个外部电芯或单个外部会话代表完整跨数据集泛化能力。

严格区分三类结果：

- `zero_shot`：目标域完全不参与训练、归一化、早停、调参或模型选择；
- `calibrated`：仅允许预先声明数量的目标域标定数据；
- `fine_tuned`：目标域样本参与模型更新。

三类结果分别建表、分别汇总，不得合并为一个通用精度。

## 3. 最低科研验收标准

第一版至少满足以下条件：

1. 纳入至少三个相互独立的数据来源；若某来源因化学体系、标签或字段不兼容而不能进入主实验，必须作为兼容性数据记录原因，并补充另一个合格来源。
2. 外部测试域包含多个独立电芯，而不是同一电芯的多个文件或会话。
3. 训练、验证和测试按照 `dataset_id`、`cell_id`、`session_id` 和 `cycle_id` 建立明确边界，窗口不得跨越边界。
4. 归一化、特征统计、早停、学习率调度和超参数选择只使用训练域与内部验证域。
5. 最终外部测试集在协议和候选模型冻结后执行，不得依据最终结果反向修改候选模型。
6. 至少包含库仑计量、简单回归、树模型、卡尔曼滤波类方法和当前 LSTM；新增深度模型必须与相同数据边界下的基线比较。
7. 随机模型至少运行五个预注册随机种子，报告均值、标准差和 95% 置信区间。
8. 报告总体、逐数据集、逐电芯、逐温度、逐 SOH、逐工况及逐 SOC 区间指标，并单独报告最差域和最大绝对误差。
9. 所有指标可以从逐样本预测文件独立重算，报告中的核心数字可追溯到运行配置、数据版本和模型哈希。
10. 失败实验、异常域和不支持结论必须保留，不得选择性删除。

第一版不预先承诺所有外部数据集 MAE 均低于 2%。数值晋级门槛在多数据集统一基线建立后，依据标签质量、数据难度和基线分布一次性冻结；冻结后不得根据最终外部测试结果修改。

## 4. 实施路线

采用数据与验证优先的分层科研路线：先冻结实验协议，再建立多数据集基准库和标签边界，然后完成基线与模型消融，最后进行跨域评估和科研交付。

模型优先路线不作为主线，因为在数据、标签和域划分尚未统一时，更换 GRU、TCN 或 Transformer 无法形成可信的归因。物理模型路线作为重要基线和后续融合方向，而不是取代统一数据协议。

## 5. 六阶段工作设计

### 5.1 阶段一：研究范围与实验协议冻结

工作内容：

- 明确第一版化学体系、数据域、预测任务和适用范围；
- 定义数据集、电芯、会话、循环、工况、温度和老化状态；
- 固定训练、内部验证、模型冻结与最终外部测试的顺序；
- 建立随机种子、运行命名、指标字典和模型晋级规则；
- 记录现有核心数据、模型和结果的 SHA-256。

阶段产物：科研实验协议、数据分割规范、指标字典、泄漏禁止清单和模型晋级规则。

退出门槛：所有已知数据的用途在模型训练前登记；最终外部测试域不能在看过结果后改变身份。

### 5.2 阶段二：多数据集基准库

工作内容：

- 审计 A123#3、A123#5 和 CX2_4 的来源、化学体系、字段、单位、采样频率、标签和电芯覆盖；
- 引入至少一个额外独立公开数据来源，并在需要时继续补充，直至满足三个合格主实验来源；
- 建立原始文件、许可证、哈希和解析状态清单；
- 统一字段与单位，但保留原始数据和转换溯源；
- 检查缺失、重复、异常范围、时间单调性、采样间隔、循环完整性和覆盖分布。

统一字段至少包括：

```text
dataset_id
cell_id
session_id
cycle_id
timestamp_s
voltage_v
current_a
temperature_c
capacity_ah
soh
soc_reference
label_method
split_role
source_file
```

退出门槛：每条标准化样本能追溯到原文件；电流方向和单位明确；数据质量问题具有数量、比例、处理方式和理由；形成机器可读数据清单与质量报告。

### 5.3 阶段三：标签与信息边界

建立两类标签：

- `offline_soc`：允许使用完整循环信息生成的离线参考标签，用于与历史结果连续比较；
- `online_available_soc`：只允许使用预测时刻及之前的信息，容量基准来自预先标定值或历史 SOH 估计。

训练输入禁止包含当前循环最终容量、未来电流、未来电压、完整循环极值、参考 SOC、测试域统计量，以及从未来标签反推的变量。

自动检查：

- 窗口是否跨数据集、电芯、会话或循环；
- 归一化是否读取验证或测试域；
- 特征在预测时刻是否真实可用；
- 测试数据改变时，训练特征和训练统计是否保持不变。

退出门槛：两类标签可复算并记录容量基准；泄漏测试能够识别人为构造的未来信息、边界跨越和统计污染；报告明确说明标签不是未经验证的物理真值。

### 5.4 阶段四：基线与模型消融

模型按以下顺序进入实验：

1. 常数和简单线性回归；
2. 库仑计量；
3. OCV/ECM 与 EKF 或 UKF；
4. 树模型；
5. 当前 LSTM；
6. GRU 与 TCN；
7. 只有现有模型存在明确且稳定的不足时，才评估 Transformer 或物理信息网络。

消融因素包括温度、历史积分电量、历史 SOH、窗口长度、采样间隔、模型容量、物理约束和传感器噪声增强。每项正式消融只改变一个主要因素。

退出门槛：所有候选方案使用相同数据边界；随机模型完成至少五个随机种子；仅内部验证稳定改善的模型可以冻结；不得使用最终外部测试结果选择模型。

### 5.5 阶段五：跨域泛化与不确定性

预注册验证矩阵包括：

- 留一数据集；
- 留一电芯；
- 留一温度区间；
- 留一工况；
- 留一老化阶段；
- 严格零样本与少量标定对照。

指标至少包括 MAE、RMSE、最大绝对误差、偏差、逐 SOC 区间 MAE、逐温度和 SOH 指标、最差电芯、五种子统计和 95% 置信区间。

不确定性模块需要验证不确定性分数与实际误差的关系，并评估分布外数据检测。模型遇到训练覆盖之外的电压、温度、容量、SOH 或特征分布时，应输出可审计的告警或拒绝预测状态。

退出门槛：所有预注册实验运行或记录明确失败原因；失败结果不删除；深度模型优势在多数外部域成立，而非仅总体平均值改善；最差域达到冻结门槛；分布外能力有量化结果。

### 5.6 阶段六：科研交付与复现

最终交付至少包括：

```text
data_manifest/
data_quality/
preprocessing/
labels/
baselines/
models/
experiments/
frozen_model/
reports/
tests/
environment/
```

提供一键预处理、训练和评估入口，固定依赖版本，保存数据与模型哈希、运行配置、日志、逐样本预测、汇总表、消融图、误差图、中文科研报告、局限和失败案例。

退出门槛：可在受支持的新环境中按说明重复生成核心结果；测试套件通过；核心指标能从预测文件独立重算；每个报告数字可追溯到唯一实验；原始数据、历史基线和新候选结果保持隔离。

## 6. 工程架构

新增科研模块，不直接重构现有桌面平台：

```text
src/research/
├── protocol.py
├── manifest.py
├── quality.py
├── schema.py
├── labels.py
├── leakage.py
├── splits.py
├── features.py
├── registry.py
├── metrics.py
├── uncertainty.py
└── pipeline.py

src/baselines/
├── constant.py
├── coulomb_counting.py
├── linear_model.py
├── tree_model.py
└── kalman_filter.py

src/models/
├── common.py
├── lstm.py
├── gru.py
└── tcn.py

configs/research/
├── protocol_v1.json
├── datasets.json
├── features.json
├── baselines.json
└── experiments.json

tests/research/
tests/baselines/
tests/models/
```

职责边界：

- `protocol.py`：科研协议、数据角色、门槛和禁止行为；
- `manifest.py`：文件清单、来源、许可证、哈希和解析状态；
- `quality.py`：数据质量统计和问题分级；
- `schema.py`：字段、类型、单位和电流方向；
- `labels.py`：两类 SOC 标签及其元数据；
- `leakage.py`：未来信息、跨边界窗口和统计污染检测；
- `splits.py`：所有预注册划分策略；
- `features.py`：仅使用历史信息的特征转换；
- `registry.py`：运行 ID、配置、状态、哈希、日志和产物登记；
- `metrics.py`：统一指标、分组指标和置信区间；
- `uncertainty.py`：不确定性和分布外评分；
- `pipeline.py`：组织阶段顺序，不直接包含模型实现。

现有 `src/training` 和 `src/evaluation` 保持可用。新模块先通过适配器调用当前 LSTM；只有在等价性测试通过后，才允许把通用模型实现迁入 `src/models`。

## 8. 数据流和状态控制

执行顺序固定为：

```text
原始文件
→ 文件清单与哈希
→ 数据质量审计
→ 统一字段与单位
→ 离线/在线标签
→ 泄漏检查
→ 冻结数据分割
→ 仅训练域拟合特征统计
→ 基线和模型训练
→ 内部验证与晋级
→ 候选模型冻结
→ 一次性外部评估
→ 指标独立重算
→ 科研报告
```

运行状态至少包含 `planned`、`running`、`failed`、`internally_validated`、`frozen` 和 `externally_evaluated`。缺少必要产物或子任务失败的运行不得进入汇总。

## 9. 错误处理

遇到以下情况停止当前实验：

- 单位、采样频率或电流方向无法确定；
- 数据来源或电芯身份缺失；
- 标签使用未来信息但未声明；
- 训练、验证和测试电芯发生重叠；
- 归一化包含验证或测试域；
- 输出目录已存在；
- 数据哈希与登记版本不一致；
- 必要模型、配置、日志、预测或指标产物缺失。

允许保留但必须量化报告：少量缺失温度、不完整循环、SOC 覆盖不足、采样协议差异、异常电芯和标签方法差异。不得静默删除。

## 10. 测试与验证

新功能严格采用测试先行的红—绿—重构流程。测试分为：

1. 单元测试：积分方向、单位转换、标签、窗口和指标公式；
2. 数据契约测试：字段、类型、范围、唯一标识和来源；
3. 泄漏测试：未来信息、跨电芯窗口和测试统计污染；
4. 小规模端到端测试：合成数据完成清单、标签、分割、训练、评估和报告；
5. 正式产物验证：配置、日志、预测、模型哈希、指标和清单完整性。

每项功能按以下顺序执行：先编写会因目标行为缺失而失败的测试；确认失败原因；实现最少代码；确认目标测试通过；运行相关回归测试；记录验证命令和结果。

任何非预期变化都会阻止当前阶段验收。新实验写入 `research_v1`，不得使用历史最终目录作为输出目录。

## 12. 第一实施周期

第一实施周期只建立可信研究基础，不训练新正式模型：

1. 编码科研协议和统一字段；
2. 生成现有核心资产清单和 SHA-256；
3. 审计 A123#3、A123#5、CX2_4 的兼容性；
4. 输出机器可读质量结果和中文质量报告；
5. 实现离线与在线标签接口；
6. 实现泄漏检测；
7. 实现留一数据集与留一电芯分割接口；
8. 使用合成数据运行端到端测试。

只有第一周期全部退出门槛通过后，才编写并执行基线与神经网络正式训练计划。

## 13. 后续计划分解

总体设计分成三个可独立验收的实施计划：

1. 研究基础计划：协议、清单、质量、标签、泄漏和分割；
2. 基线与候选模型计划：物理基线、传统模型、LSTM/GRU/TCN 和消融；
3. 跨域验证与交付计划：预注册验证矩阵、不确定性、外部冻结测试和科研报告。

每个计划只有在前一计划产物和退出门槛验证完成后启动。
